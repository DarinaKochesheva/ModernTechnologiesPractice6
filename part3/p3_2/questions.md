# Вопросы по Hibernate - Часть 3

## Вопрос 1: JDBC vs Hibernate

**Вопрос:** В чем разница между JDBC и Hibernate?

**Ваш ответ:**

JDBC — это низкоуровневый API для работы с базами данных, где нужно вручную писать SQL-запросы, создавать Connection, Statement, обрабатывать ResultSet и закрывать ресурсы. Hibernate — это ORM (Object-Relational Mapping) фреймворк, который автоматически преобразует Java-объекты в записи базы данных и обратно, избавляя от ручного написания SQL.

Основные различия:
- Уровень абстракции: JDBC работает с таблицами и строками, Hibernate — с объектами
- SQL: в JDBC пишете SQL вручную, в Hibernate генерирует SQL автоматически
- Производительность: JDBC быстрее, Hibernate удобнее для сложных связей
- Код: JDBC требует больше кода, Hibernate сокращает его за счет аннотаций

## Вопрос 2: HQL vs SQL

**Вопрос:** Что такое HQL и чем он отличается от SQL?

**Ваш ответ:**

HQL (Hibernate Query Language) — это объектно-ориентированный язык запросов Hibernate, который работает с Java-классами и их полями, а не с таблицами и столбцами базы данных.

Отличия HQL от SQL:
- Синтаксис: HQL оперирует именами классов и полей (FROM Movie WHERE genre = :genre), SQL — именами таблиц и столбцов (FROM movies WHERE genre = 'sci-fi')
- Понимание БД: HQL не зависит от конкретной СУБД, SQL зависит от диалекта
- Возвращаемый результат: HQL возвращает объекты Java, SQL — ResultSet
- Связи: HQL поддерживает навигацию по объектным связям

## Вопрос 3: Аннотации Hibernate

**Вопрос:** Какие основные аннотации Hibernate используются на сущности Movie?

**Ваш ответ:**

- @Entity — указывает, что класс является сущностью и будет сохранен в базу данных
- @Table(name = "movies") — задает имя таблицы в БД для этой сущности
- @Id — обозначает первичный ключ таблицы
- @GeneratedValue(strategy = GenerationType.IDENTITY) — определяет стратегию генерации значений для первичного ключа
- @Column(name = "title", nullable = false) — связывает поле с колонкой таблицы, указывает

### Ответ 1: JDBC vs Hibernate

**JDBC (Java Database Connectivity):**
- Низкоуровневый API для работы с БД
- Прямая работа с SQL запросами
- Ручное управление соединениями
- Ручное маппинг ResultSet → объекты
- Больше boilerplate кода

**Hibernate (ORM):**
- ORM (Object-Relational Mapping) фреймворк
- Работа с объектами, а не с SQL
- Автоматическое управление сессиями
- Автоматическое маппинг объектов ↔ таблицы
- Меньше кода, выше абстракция
- HQL вместо SQL (хотя SQL тоже можно)

### Ответ 2: HQL vs SQL

**HQL (Hibernate Query Language):**
- Объектно-ориентированный язык запросов
- Работает с классами и полями, не с таблицами и столбцами
- `FROM Movie WHERE genre = 'sci-fi'` - Movie это класс, genre это поле
- Переносим между разными БД (Hibernate генерирует нужный SQL)
- Поддерживает наследование, полиморфизм

**SQL:**
- Структурированный язык запросов
- Работает с таблицами и столбцами
- `SELECT * FROM movies WHERE genre = 'sci-fi'`
- Зависит от диалекта БД

### Ответ 3: Аннотации Hibernate

**Основные аннотации на сущности Movie:**

1. **@Entity** - помечает класс как JPA сущность
2. **@Table(name = "movies")** - указывает имя таблицы в БД
3. **@Id** - помечает поле как первичный ключ
4. **@GeneratedValue(strategy = GenerationType.IDENTITY)** - автогенерация ID
5. **@Column(name = "title", nullable = false)** - настройка столбца:
   - `name` - имя столбца
   - `nullable` - может ли быть NULL

**Дополнительные распространенные аннотации:**
- **@OneToMany**, **@ManyToOne** - связи между сущностями
- **@Temporal** - для полей Date/Calendar
- **@Enumerated** - для enum полей
- **@Transient** - поле не сохраняется в БД
